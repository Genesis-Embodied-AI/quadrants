# Measure stack storage during backward

Adstack replay measures stack requirements immediately before each `.grad()` call or Tape backward. Forward calls require no context manager or recording handle. Backward-only kernels and repeated backwards use their current arguments and state.

Backward first executes a count-only version of its reduced primal replay, allocates measured storage, then runs the normal recording/reverse pass. Counting does not write output values or gradients. This adds a reduced replay and synchronization to each backward; it does not cache sizes by argument contents. A small measurement buffer is reused and cleared for each backward; CPU/CUDA read both measurement words directly, while SPIR-V uses the portable array-copy path.

CPU (x64), CUDA, Vulkan, and Metal code paths are implemented. Stack accesses remain bounded if recording exceeds the measurement, and the host raises after execution; discard gradients from a failed backward. Counting removes non-differentiable output writes and computations used only by those outputs, including diagnostic flag updates. Remaining reads must be separate from the removed writes: distinct fields/arrays, or distinct frame slices indexed by an i32 scalar argument plus a constant. Other read/write dependencies are rejected rather than executed twice. For array arguments, a conservative runtime check rejects overlapping storage when either argument is non-differentiable; it also rejects mixed native/external array bindings on SPIR-V when their aliasing cannot be checked. Other initial restrictions include random/internal operations, while/continue/return, sparse fields, graphs/checkpoints, and custom streams. Vector stacks are scalarized automatically. These restrictions are being evaluated against Genesis.

Legacy sizing code is removed. Every backward uses replay counting; unsupported cases raise instead of falling back. The old `ad_stack_experimental_enabled`, `ad_stack_size`, `ad_stack_sparse_threshold_bytes`, and `ad_stack_replay_count` options are removed. Persistent caches distinguish this runtime layout from the original counted-only and legacy layouts, as well as distinguishing counting, measured backward, and ordinary kernels.

Genesis kernel call sites need no counting scopes. Remove the obsolete sizing options from its `qd.init` call when using this branch. Compare legacy performance using a separate legacy build/process, never an in-process mode switch.
